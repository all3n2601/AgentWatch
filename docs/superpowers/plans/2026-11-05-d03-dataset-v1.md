# D03 dataset v1 (`steps-v1.3`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One rebuildable `steps-v1.3` release holding the CPU/coding runs and Benoy's 54 replay
experiments (labels-v2, `step-features-v1`), gated by TFDV, split with `split-v2` under
`eval-contract-v2`, with schema, missingness, class-balance and leakage statistics.

**Architecture:** Replay experiments become a second kind of evidence-store entry. The build
labels each stored experiment with the unchanged `label_experiment`, joins `step-features-v1`
rows computed from the same replay's journal, and appends those rows after the run rows in one
release. `splits.py` dispatches on the contract's `method`: `split-v1` produces exactly the old
documents; `split-v2` calls `split_assignment.partition_v2` and records the D02 checks, class
balance and a report-only design-encoding table.

**Tech Stack:** Python 3.13, uv workspace, pyarrow, pydantic (SDK live models),
TFDV (`pipelines/validation`, own environment), DVC, pytest, Ruff.

**Spec:** `docs/superpowers/specs/2026-11-05-d03-dataset-v1-design.md`

## Global Constraints

- Branch `feature/d03-dataset-v1`; commit titles `<type>: <change>`; no Claude co-author
  trailer or PR footer (owner's rule for this repo). Commit only; push and PR only when the
  owner asks.
- Null is never zero: a reading the journal lacks stays null; a missing `passed` stays null and
  fails the schema, it is never coerced to `False`.
- `labels.toml`, `labels-v2.toml`, `split-assignment.toml` and every contract threshold are
  unchanged.
- `steps-v1.2+5954f97ef8b2`, `split-v1+58e921fa846a`, `pipelines/validation/schema/steps.pbtxt`
  and the v1 contract content must keep loading: `load_split(…, evaluation-contract-v1.toml,
  steps.pbtxt)` returns the same rows as before this branch.
- `RELEASE_FORMAT` stays `2` (`verify_release` refuses any other format, which would break the
  v1.2 split). Manifest statistics are part of the `steps-v1.3` schema version instead.
- Feature-timing tolerance `1e-6` s (absolute). Leakage bound and minimums come from the
  contract (`0.98`; `30` per class, `100` clean, `30` mixed).
- Replay entry name: `replay-<plan.task_id>-<started_at UTC %Y%m%dT%H%M%SZ>-<first 6 hex of
  SHA-256 of experiment.json bytes>`.
- Allowed entry files, as POSIX paths relative to the entry: `experiment.json`,
  `source/agent-evidence.json`, `source/live-journal.jsonl`, `replays/NN/agent-evidence.json`,
  `replays/NN/live-journal.jsonl`, `injections/NN.json` (`NN` = two digits). Nothing else, no
  symlinks.
- Untrusted input: run Python that reads Benoy's extracted evidence with `-I`; pass evidence
  paths as arguments.
- Storage changes here are file stores, not PostgreSQL; the DB integration suite still runs in
  the final verification with `AGENTWATCH_TEST_DATABASE_URL`.

## Review Focus

1. **The same experiment delivered twice under different folder names** (batch 1 was
   re-uploaded once): the content-derived entry name makes the second add a no-op that prints
   `already stored`. Test in Task 1.
2. **A journal with a malformed line, or a record for another run**: the experiment is refused
   at curation and nothing is staged in the store. Test in Task 1.
3. **One unusable step in a good experiment** (zero-duration step with null `queue_fraction`,
   or a feature row missing): only that step is rejected, with its code; the experiment's other
   rows stay. Tests in Task 3.
4. **The v1.2 release and its `split-v1` split after this branch**: same split id, same rows,
   when given the v1 contract and `steps.pbtxt`. Test in Task 6, real check in Task 9.
5. **A stored experiment edited after a release used it**: integrity refuses the release as
   built from evidence not in the store. Test in Task 5.

    `replay_evidence.MAX_EVIDENCE_BYTES`, every line through `extract.parse_jsonl`; line `kind`
    must be one of `registration`, `run_created`, `run_change`, `record`; a `record` payload's
    `record_type` must be `step_event` or `resource_sample` and validate with
    `agentwatch_sdk.live.StepEvent` / `ResourceSample`; all records must share one `run_id`.
    Any violation raises `ReplayEvidenceError` naming the line number.
  - `evidence.REPLAY_PREFIX = "replay"`, `evidence.EXPERIMENT_FILE = re.compile(...)` matching
    exactly the allowed paths in Global Constraints.
  - `evidence.experiment_entry_name(manifest: bytes, experiment: Experiment) -> str`.
  - `evidence.add_experiment(directory: Path, store: Path) -> Stored`.
  - `evidence.read_stored_experiment(path: Path) -> tuple[Experiment, dict[str, str]]`
    returns the experiment and `{relative path: sha256}` for every file; raises
    `EvidenceError` on extra files, symlinks, unreadable experiment or journal.
  - `evidence.add(path: Path, store: Path) -> Stored`: `add_experiment` when
    `path / "experiment.json"` exists, else `add_run`. `main` calls `add`.
  - `replay_fixtures.write_experiment(..., live: bool = False, started_at: str =
    "2026-11-05T00:00:00+00:00", passed: bool | None = True)`. With `live=True` each replay's
    journal holds a `registration` line (with `configuration_digest`), SDK-valid
    queued/running/completed `step_event` records per step whose ticks reproduce the step's
    total/queue/execution seconds exactly, and `cpu.psi.some.avg10.v1` samples every 0.25 s on
    the tool step's resource; `agent-evidence.json` gains
    `configuration: {"sampling_interval_seconds": 0.25}` and `configuration_digest`; `source/`
    gets the same two files as replay 00. `started_at` and `passed` go into `experiment.json`.

    `split_method`. `read_split_file` takes the prefix from the file's `split_method` (must be
    in `METHODS`). `load_split` returns `members_for(...)[1][name]`.
